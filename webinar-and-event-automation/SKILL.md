# Webinar and Event Automation

## What this skill does

Builds the automation spine for events so registrations become pipeline: timely reminders lift attendance, and behaviour-based follow-up goes out while intent is warm.

## Inputs to collect

- Event platform and registration data fields
- Email/CRM stack and available integrations
- Follow-up offers by segment (attendee, no-show, engaged)

## Workflow

1. **Design the registration flow** - Minimal form (name, work email, one qualifying question max), instant confirmation with calendar file and what-to-expect. Every extra field costs registrations - price them consciously.
2. **Build the reminder ladder** - Confirmation, value reminder (day -3 with a reason to attend), logistics (day -1), and starting-now (hour -1). Each with the join link unmissable.
3. **Capture behaviour as data** - Sync attendance, watch duration, poll/chat engagement and questions asked back to the CRM as fields/tags. Behaviour, not registration, drives follow-up quality.
4. **Segment the follow-up** - Engaged attendees: conversation offer + resources within 24h. Attended-passive: replay + key content. No-shows: replay + honest subject line (never fake 'you missed your seat' pressure). Each path tested.
5. **Close the reporting loop** - Per event: registrations by source, attendance rate, engaged rate, follow-up conversions, pipeline at 30/60 days - written into the event template for next time.

## Deliverable

- Automation map: registration to follow-up
- Reminder and follow-up email set per segment
- Event reporting template with CRM fields

## Success metrics

| Metric | How to read it |
|--------|---------------|
| Registration-to-attendance rate | Reminder ladder's report card |
| Engaged attendee share | The audience that matters for pipeline |
| Follow-up conversion within 24h window | Speed is the variable this automation exists to win |

## Quality checklist

- [ ] Calendar invite and join link in the confirmation email
- [ ] All follow-up branches tested with seed records
- [ ] Attendance data verified in the CRM after a test event

## Guardrails

- Claims discipline: use only proof the user supplies or verifies. Never invent clients, results, rankings, or testimonials.
- Privacy and consent: collect and use personal data only with a lawful basis and consent where required. Respect PDPA (Singapore) and GDPR; honour unsubscribes and opt-outs immediately.
- Platform policy: follow each ad and search platform's current policies. When a rule changes often, flag it for a human to re-check before launch.
- Automation amplifies whatever it touches - verify data and logic on test records before any workflow touches the live list.
- Consent travels with the contact: a workflow must never re-subscribe, re-permit or message someone outside the consent they gave.
