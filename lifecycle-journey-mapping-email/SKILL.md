# Lifecycle Journey Mapping (Email)

## What this skill does

Connects the flow architecture to real customer stages, exposing where the programme goes silent exactly when the customer needs to hear something.

## Inputs to collect

- Customer stages and their behavioural definitions
- Current flows and campaign calendar
- Stage transition data (counts, time in stage)

## Workflow

1. **Define stages behaviourally** - New subscriber, activated, first purchase, repeat, at-risk, lapsed, advocate - each with a data definition, not a feeling.
2. **Plot current coverage** - For each stage: what emails exist, their cadence and their performance. Mark the silent stages - usually post-purchase and at-risk.
3. **Find the money gaps** - Rank gaps by stage size x transition value: moving 5% more first-purchase to repeat usually beats polishing the welcome flow again.
4. **Design the missing messages** - For each priority gap: the trigger, the message's single job, and the proof or help it provides. Education and service first, offers second.
5. **Set stage health metrics** - One transition metric per stage boundary, reviewed monthly. The map becomes a dashboard, not a poster.

## Deliverable

- Lifecycle map with coverage and silence gaps
- Priority gap list with designed messages
- Stage transition metric set

## Success metrics

| Metric | How to read it |
|--------|---------------|
| Stage transition rates | The lifecycle's vital signs |
| Revenue per stage per month | Shows where the programme earns |
| Silent-stage count | Should trend to zero for key stages |

## Quality checklist

- [ ] Stages defined by data events
- [ ] At-risk and post-purchase stages explicitly covered
- [ ] Every designed message has one job

## Guardrails

- Claims discipline: use only proof the user supplies or verifies. Never invent clients, results, rankings, or testimonials.
- Privacy and consent: collect and use personal data only with a lawful basis and consent where required. Respect PDPA (Singapore) and GDPR; honour unsubscribes and opt-outs immediately.
- Platform policy: follow each ad and search platform's current policies. When a rule changes often, flag it for a human to re-check before launch.
- Permission-based sending only: no purchased or scraped lists, ever. Clear consent, honest sender identity, one-click unsubscribe in every email.
- Deliverability is trust: no deceptive subject lines, no hidden downsides, no dark patterns in preference or unsubscribe flows.
