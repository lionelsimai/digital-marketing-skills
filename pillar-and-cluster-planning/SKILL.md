# Pillar and Cluster Planning

## What this skill does

Designs the content architecture for one topic at a time: a comprehensive pillar, cluster pieces for sub-intents, and the linking rules between them.

## Inputs to collect

- Keyword map for the topic
- Existing content on the topic (audit list)
- The commercial page this cluster should ultimately support

## Workflow

1. **Choose the pillar topic** - A topic broad enough to matter commercially, narrow enough to cover definitively, and inside the brand's real expertise.
2. **Map the sub-intents** - List cluster queries by intent: definitions, how-tos, comparisons, mistakes, tools, examples. Each becomes one cluster piece with one job.
3. **Assign the linking rules** - Clusters link up to the pillar with descriptive anchors; pillar links down to clusters; clusters cross-link only where a reader benefits.
4. **Sequence the build** - Pillar first (or upgrade the best existing page), then clusters in intent-value order. Don't publish 20 clusters pointing at a pillar that doesn't exist.
5. **Plan the commercial bridge** - Decide how the cluster hands off to the offer: relevant CTA placement on pillar and high-intent clusters, without turning guides into ads.

## Deliverable

- Cluster map: pillar, pieces, intents, links
- Build sequence with briefs queued
- Internal linking rule sheet for the topic

## Success metrics

| Metric | How to read it |
|--------|---------------|
| Cluster visibility (share of cluster queries in top 10) | The authority signal |
| Pillar page conversions/assists | Authority must eventually pay |
| Cannibalisation incidents in the cluster | Caught via the keyword map review |

## Quality checklist

- [ ] Each cluster piece has a distinct intent
- [ ] Pillar genuinely covers the topic end to end
- [ ] Expertise check: a practitioner would respect this cluster

## Guardrails

- Claims discipline: use only proof the user supplies or verifies. Never invent clients, results, rankings, or testimonials.
- Privacy and consent: collect and use personal data only with a lawful basis and consent where required. Respect PDPA (Singapore) and GDPR; honour unsubscribes and opt-outs immediately.
- Platform policy: follow each ad and search platform's current policies. When a rule changes often, flag it for a human to re-check before launch.
- Original or properly licensed content only. No plagiarism, no scraped articles, no AI-spun rewrites of competitors' work.
- Statistics and quotes must trace to a real source the reader can check.
