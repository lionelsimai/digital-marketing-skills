# Referral Programme Design

## What this skill does

Builds referral as a product feature, not a begging email: the ask lands when value is felt, the reward serves both sides, and the mechanics can't be gamed.

## Inputs to collect

- Moments of peak user value in the product/service journey
- Margin room for incentives and their unit economics
- Current word-of-mouth baseline (how people already refer)

## Workflow

1. **Find the natural share moments** - After a result, a milestone, a delivered report, a saved hour - moments where the user feels the value and knows who else needs it. Engineer prompts there, not in a settings page.
2. **Design the two-sided incentive** - Reward both referrer and referee where margins allow, in currency the audience values (credit, features, time) - and test whether the incentive even matters vs pure goodwill for your users.
3. **Make sharing effortless and honest** - Pre-written messages the user can edit, sent from their own channels with their consent. Never import contacts, never auto-send, never message anyone the user didn't explicitly choose.
4. **Build the anti-fraud rules** - Self-referral blocks, device/account signals, reward only after the referee's genuine activation/payment, and caps. Publish the rules plainly.
5. **Measure the loop, not the clicks** - Track invites per active user, invite-to-signup, signup-to-customer, and the referred cohort's retention vs baseline. A loop that brings churners is a cost, not a channel.

## Deliverable

- Referral programme spec: moments, incentives, mechanics, rules
- Share copy set (editable by users)
- Loop measurement dashboard spec

## Success metrics

| Metric | How to read it |
|--------|---------------|
| Invites per active user per month | The loop's top of funnel |
| Referred customer retention vs baseline | Quality gate for the whole programme |
| Fraud/reward-abuse rate | Caught by the rules - should stay tiny |

## Quality checklist

- [ ] No contact importing or auto-sending anywhere in the design
- [ ] Rewards trigger only on genuine referee value events
- [ ] Rules published in plain language to participants

## Guardrails

- Claims discipline: use only proof the user supplies or verifies. Never invent clients, results, rankings, or testimonials.
- Privacy and consent: collect and use personal data only with a lawful basis and consent where required. Respect PDPA (Singapore) and GDPR; honour unsubscribes and opt-outs immediately.
- Platform policy: follow each ad and search platform's current policies. When a rule changes often, flag it for a human to re-check before launch.
- Growth never overrides consent or honesty: no spam invites, no contact scraping for referral mechanics, no dark-pattern virality.
- Experiments on pricing and billing must be transparent to affected users - no silent price tests on existing customers' renewals.
- Referral mechanics must never message a user's contacts without that user explicitly choosing each recipient and sending it themselves.
